# Fortuna 1.8.3 HoldingTxns 恢复验证

日期：2026-10-16。Android versionCode：19；iOS build：19。

## 问题与修复

旧校验直接使用工作表原始类型，因此文本形式的合法数字和 Excel 日期单元格无法恢复。可选 `quantitySnapshot`、`costPriceSnapshot` 写成空字符串时也会被当作无效数据。新增测试在修复前均可复现。

- 数字仅在整个单元格符合数字格式时转换；空白必填项、单位文字、错误千分位和布尔值不会转换成零。
- 空白可选校准字段视为未提供；真正的零数量、零成本校准保留为零。
- Excel 日期通过 SheetJS 日期解析器转换，兼容 1900 与 1904 日期系统；无效日期和含有时间的数字不被静默截断。
- 校验失败显示实际工作表行号、字段和原因；空白行不会使报告行号错位。账户与持仓引用必须完整且一致。
- 保留全部校验先于写入、完整替换、失败整批回滚的恢复方式。

Node 使用 SheetJS 的 CommonJS 默认导出，生产网页使用 ES module 命名导出；两种运行环境均已检查。

## 验证

- `npm test`：226 项通过，16 项备份相关测试涵盖格式转换、精度、零值、无效字段、重复 ID、引用完整性、覆盖替换、并发导出及写入回滚。
- `npm run lint`、`npm run build`、`git diff --check`：通过。
- 最终网页构建已同步至 Android、iOS；`npm run ios:verify` 检查 43 项网页资源一致。
- 生产网页 UI：恢复合成工作簿中的文本数字、空白校准字段、零数量校准及 Excel 日期；逐字段核对交易内容。
- 重复导入及导出后重新恢复保持账本内容一致。
- 无效成本校准与缺失持仓显示具体字段；关闭弹窗后错误仍可查看；逐表核对失败前后数据一致。
- 320×568 和 390×844 均无横向或纵向越界，小屏弹窗可滚动；无页面运行时异常。

浏览器结果：[holding-txns-browser-validation.json](holding-txns-browser-validation.json)。复现工作簿均使用合成数据。

## 验证边界

以上证明格式兼容和数据保护行为，不能证明任何未提供的工作簿内容完整。实体手机的文件提供程序、恢复及覆盖安装尚未验证。正式签名包及在线更新另行验证。
