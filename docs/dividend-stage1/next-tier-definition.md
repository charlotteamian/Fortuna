# 阶段1.1：“下一档”的只读定义

2026-10-31。实现前按 `buildGrid` / `buildDividendHomePlan` 的现有累计目标和持仓规则确定；不增加策略、成交记录或定价公式。

- 买入下一档是原顺序中**累计目标股数大于当前持仓**的第一档。累计目标直接读取原引擎的 `targetShares`，不将每档25%当成新增订单。若差额不足一手，保留该档并标 `below_lot`；所有目标均已覆盖时无下一档、状态为 `covered`。预算未加载/价格不完整时为 `unknown`，预算为零为 `budget_empty`，均不能宣称目标已覆盖。
- 卖出下一档是原顺序中**按当前持仓计算的累计卖出数大于零**的第一档，读取原引擎的 `sellShares`。零持仓时无下一档、状态为 `no_holding`。当前没有逐档卖出进度账本，不能从价格已经越过某档或当前持仓反推该档已经执行，也不能自行跳过为“下一次成交档”。
- `nextBuy` / `nextSell` 保留原档号。`basis=cumulative_target` 表示目标已知；部分缺价仅能提供首个合法原档的 `basis=price_reference`，状态为 `unknown`，不附股数、不把它当作已确定的下一操作目标。完全无合法价则不返回价格对象。
- 下一档是持仓目标参考，与今日触价和操作资格分开。多档同时触价仍由既有 `trigger.*Levels` 和原引擎最深到价累计目标计算总差额；手动暂停只限制操作，不改变下一档价格事实。

例子（沿用原引擎产生的累计目标）：

| 情况 | 结果 |
| --- | --- |
| 累计买入目标为200/500/800/1100股，持仓0 | 下一买档为原第1档，目标200股 |
| 同上，持仓500股 | 下一买档为原第3档，目标800股 |
| 同上，持仓1100股或更多 | 无下一买档，`covered` |
| 同上，持仓150股、每手100股 | 第1档尚差50股，`below_lot`，不虚构100股新增订单 |
| 缺原第1档价格，仅原第2档10元有合法价 | 第2档10元仅作 `price_reference`，`unknown`，无累计股数 |
| 四个买档均到价 | 触价保留四个原档号；下一未覆盖目标与本轮总差额各自保留，不将最深触价当成交历史 |
| 持仓100股，四个卖档各25% | 前三档整手卖出为0，第4档原引擎可退出100股，下一卖档为第4档 |
| 持仓0，卖价已越过所有档位 | 触价事实保留，下一卖档为空，`no_holding` |
| 手动暂停且第2档尚未覆盖 | 下一买档和价格仍为第2档，买入操作仍受暂停限制 |

基金继续使用原单一入场/退出条件和价格，不套用股票累计网格。

## 特别分红相关性

复核只针对本次基数选中批次、已提供保存证据中参与本次比较的批次、影响选中批次股本归一化的事件，或确实导致本次报价/旧网格除息复核的最新事件。选中批次尚未核验或冲突仍属本次未决事项。未选中、未参与比较和股本调整的旧特别分红不产生持续买入复核限制。

每个相关特别分红分别携带该事件自己的来源、所属期、公告日和原核验日；未知保持缺失。未核验或冲突事件不能继承普通分红的核验日期，多个相关事件也不合成一个来源/日期混杂的条目。

已公告未实施预案仍由原台账单列，不因这一提示被纳入、附加或替换基数。是否改变特别分红的业务纳入规则继续待用户决定。
