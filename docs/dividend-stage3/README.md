## 调度、排序及日期口径

- 继续使用 `prepareDividendAdvisorContext`、现有行情/分红/研究/巨潮服务、`dividendCheckSummary` 和基金引擎。没有新建定价或风控引擎。资料刷新只更新明确的行情、证据、研究与检查缓存。
- 一轮按行情 → 公告/财报 → 计划核验 → 结果推进。股票分红最多 3 路、研究沿用最多 4 路并发；研究自身原有数量/时间预算仍保留。行情之后、逐只研究完成之后都会重读可用资料，最终再核验当前计划。完成后的阶段明细默认收起。
- 需处理：已知股票原则不通过、手动暂停、已有阻断，或共享摘要要求复核/人工确认。其后是无法判断，最后是等待。同组优先显示观察到价，再按稳定计划键排序，不按风险数量打分。基金“入场条件未满足”保留为等待，不当作股票原则不通过。
- 去重键为 `stock:<code>` / `fund:<id>`；同一基金代码下不同保存计划保留各自身份。每项显示名称代码、所用行情及源时间、原档号/累计下一目标或基金参考、买卖约束和最多三条主因，跳转原计划的同一依据区。所有数值与状态来自共享摘要。
- 覆盖按唯一资料检查项计数，不是证券数量，也不是物理 HTTP 请求数：每项行情、分红、日期补充、各研究来源、正式公告覆盖、计划核验及公共市场参考各有身份。研究聚合占位结束后不与具体来源重复计数。手工基金参考标明未下载，缺失的交易报价保留延期/未知。
- 批次开始/结束、截止时间、请求尝试时间、来源报告/公告日期、原 PDF 核验日期分别记录。重用 PDF 不改核验日；全部失败或部分失败都保留最后成功资料与原逐股研究日期。技术资料下载成功不能替失败的财务核验改日期。
- 到价只表示价格观察。没有交易时段、停牌、券商现金、费用与流动性证明，因此不写成已具备实际成交条件。

## 停止、重试与结果保留

- 重复点击共用一轮任务。离开页面、后台化、打开其他阅读流程或显式取消会传递同一停止信号。停止后不再发起后续请求；web 请求与 PDF 工作使用取消信号。
- 原生 HTTP 不能由 Capacitor 物理中止：等待会被解除，迟到响应不能进入解析后的业务提交。界面明确说明底层调用可能仍在返回，不宣称所有物理请求已结束。每次缓存写入前检查批次、停止信号和用户输入；相关写入事务也检查停止状态。原生覆盖是模拟调用，不是真机证明。
- 整轮来源工作与调度受 90 秒截止控制，包括初次读取、后续读取和来源刷新。终态先显示，再尝试最多 1 秒的本机检查结果落盘；落盘失败明确提示，不无限等待存储。不能取消的外部调用即使继续运行也不能回写本轮。
- 单项重试只请求所选失败计划；没有重刷其他股票、基金或公共市场来源。重试前、来源提交前和结束时重读输入；其他项目语义改变时标记过期，不能把未重试的新状态冒充已检查。公共市场来源失败需要整轮重查。
- `FortunaDividendDailyAdvice` 继续使用现有 v1 `advice: id` 表；增加 `check:current` 与 `check:completed` 两个结果记录身份，不改建表定义。原 `latest` 建议记录不覆盖、不迁移。批次所有权和递增修订号阻止旧进度恢复到新终态；完成记录不被本轮部分/取消结果覆盖。
- 跨日、计划/持仓/税率、价格或证据实质变化会提示重查；仅重新下载同一数据不会无谓失效。相同未保存计算的批次时间也不视为价格变化。记录只保存允许的检查字段，不保存模型配置或凭证；损坏结果忽略但不删除旧记录。
- AI 解释位于清单之后。它只读取已有上下文，使用 1.2 的本地返回和引用协议，不刷新资料、不生成本轮动作、不替代确定性检查。模型未配置也可读取本地解释。
